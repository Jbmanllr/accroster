# Existing tools: usage trackers, account switchers, session browsers

Survey for [issue #2](https://github.com/Jbmanllr/claude-account-manager/issues/2): what already exists for (a) Claude plan usage in the macOS menu bar or terminal, (b) switching Claude Code and Claude desktop accounts, and (c) browsing Sessions across projects and accounts. For each serious candidate: what it does, where its usage figures come from, how it stores credentials, how it switches, and its health. Ends with what to reuse, the pitfalls these tools hit, and the gaps this app would fill.

Researched 2026-10-24. Stars, licenses, last push and latest release come from the GitHub REST API (`repos/{owner}/{repo}`, `releases/latest`) on that day; crate data from the crates.io API. Tool behavior comes from each project's README, docs or source on its default branch, and is marked as the project's own claim where it could not be checked against Anthropic. No credentials were read; the only local inspection was the field names and sample counts of one desktop app file (see [Usage sources](#where-usage-figures-come-from)).

Vocabulary follows the [map issue #1](https://github.com/Jbmanllr/claude-account-manager/issues/1): **Profile** (one claude.ai Login within one Organization), **Session limit** (rolling 5-hour), **Weekly limit** (7-day), **Active Profile**, **Unified session view**, **Sidebar sync**.

## Answer in brief

- **The field is crowded and moves fast.** GitHub searches on 2026-10-24 return dozens of macOS menu bar trackers, account switchers and session browsers pushed in the last month. The leaders are [CodexBar](https://github.com/steipete/CodexBar) (22.8k stars, Swift), [ClaudeBar](https://github.com/tddworks/ClaudeBar) (1.6k, Swift), [Claude-Usage-Tracker](https://github.com/hamed-elfayome/Claude-Usage-Tracker) (3.7k, Swift), [claude-swap](https://github.com/realiti4/claude-swap) (4.0k, Python), [ccusage](https://github.com/ccusage/ccusage) (19.2k, Rust) and [claude-code-history-viewer](https://github.com/jhlee0409/claude-code-history-viewer) (2.3k, Tauri).
- **Nobody combines all three jobs in a Rust menu bar app inside our safety bar.** Swift apps own the menu bar; Rust tools are TUIs, Waybar widgets or Windows trays. The closest designs are ClaudeBar (per-Profile `CLAUDE_CONFIG_DIR` folders plus a shell wrapper for "which login new sessions use") and CodexBar's `claude-swap` adapter. Neither shares transcripts across Profiles, and neither offers a Unified session view or desktop switching.
- **Live per-Profile limits all come from one undocumented endpoint**, `GET https://api.anthropic.com/api/oauth/usage` with the Profile's OAuth token. Anthropic offers no official usage API for Pro/Max ([anthropics/claude-code#99231](https://github.com/anthropics/claude-code/issues/99231), open). The endpoint is rate limited per account, and Anthropic's own `/usage` falls back to last-known figures when it is ([Costs docs](https://code.claude.com/docs/en/costs)).
- **The hardest pitfalls are credential handling.** Refresh tokens are single use, so any second copy of a credential goes stale or gets the Profile logged out. Short-lived `claude` commands can burn a refresh token. Keychain grants are bound to the calling binary. Anthropic's terms forbid third parties from collecting, storing or intermediating claude.ai credentials ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)), and most switchers do exactly that.
- **The safest pattern seen** gives each Profile its own Claude-owned config dir, with its own Keychain item that Claude Code creates and refreshes itself. It symlinks shared state, including `projects/`, back to `~/.claude` ([ccsw](https://github.com/jv-vogler/ccsw), [caam](https://github.com/Dicklesworthstone/coding_agent_account_manager)). The CLI switches through a wrapper or file that sets `CLAUDE_CONFIG_DIR` for new runs ([ClaudeBar "In use"](https://github.com/tddworks/ClaudeBar/blob/main/docs/features/in-use/README.md)). The menu bar app then never mints, copies or rewrites a token.

- **ClaudeBar:** a token refresh requested fewer scopes than Claude Code and dropped `user:mcp_servers`, breaking claude.ai connectors ([#593](https://github.com/tddworks/ClaudeBar/issues/593)). An update broke the Claude connection on macOS ([#557](https://github.com/tddworks/ClaudeBar/issues/557)).
- **Claude-Usage-Tracker:** a Profile switch wrote a stale credential snapshot to the Keychain after `invalid_grant`, logging Claude Code out ([#331](https://github.com/hamed-elfayome/Claude-Usage-Tracker/issues/331)). Profile switching rotted credentials on single-`~/.claude` setups ([#263](https://github.com/hamed-elfayome/Claude-Usage-Tracker/issues/263)). Non-active Profiles never refresh ([#335](https://github.com/hamed-elfayome/Claude-Usage-Tracker/issues/335)). The history file grows 10–17 GB an hour ([#337](https://github.com/hamed-elfayome/Claude-Usage-Tracker/issues/337)). Statusline scripts are rewritten on every launch without backup ([#321](https://github.com/hamed-elfayome/Claude-Usage-Tracker/issues/321)).

## (b) Account switchers

Three switching mechanisms exist:

1. **Swap the global credential in place.** Write another account's token into `Claude Code-credentials` and its `oauthAccount` block into `~/.claude.json`. Used by claude-swap, CCSwitcher, Claude-Usage-Tracker, clauth (`clauth <name>`), cc-account-switcher and Symbioose. It affects running sessions too: the CLI re-reads the Keychain about every 30 seconds ([claude-swap README](https://github.com/realiti4/claude-swap)), or on its next call ([CCSwitcher README](https://github.com/XueshiQiao/CCSwitcher)). That violates the map's "running Sessions never change Profile".
2. **One config dir per Profile, chosen at launch.** Set `CLAUDE_CONFIG_DIR`, with shared state symlinked back. Used by ClaudeBar "In use", ccsw, caam, quinnjr/claude-code-profiles, clauth `start`, swapdex and silo. Running sessions keep their Profile ([ClaudeBar "In use"](https://github.com/tddworks/ClaudeBar/blob/main/docs/features/in-use/README.md)).
3. **Proxy per request.** A local gateway picks the account for each request. Used by tcr and loekj/claude-acct-switcher (Van Damme-o-Matic, which also sends `max_tokens: 0` keep-warm pings). Out of scope for this app.

## Pitfalls these tools hit

1. **Refresh tokens are single use; copies go stale.** A second holder of the same credential either goes stale or invalidates the first. claude-swap avoids running a second copy of the active credential ("would go stale") and captures rotated tokens back ([README](https://github.com/realiti4/claude-swap)). nerlichman/claudebar will not refresh the CLI's token because "rotating that token would invalidate it under a running CLI" ([README](https://github.com/nerlichman/claudebar)). Anthropic's own issues show concurrent processes wiping `claudeAiOauth` ([#88583](https://github.com/anthropics/claude-code/issues/88583), [#80085](https://github.com/anthropics/claude-code/issues/80085), [#76561](https://github.com/anthropics/claude-code/issues/76561)). Snapshot-and-swap switchers (CCSwitcher, Claude-Usage-Tracker, clauth) inherit this risk ([Claude-Usage-Tracker#331](https://github.com/hamed-elfayome/Claude-Usage-Tracker/issues/331)).
2. **Short-lived `claude` commands can burn the refresh token.** `claude auth status`, `doctor` and `--bg` start a refresh at init and exit before saving it. A tool that ran `claude auth status` per profile every few minutes logged profiles out ([#95822](https://github.com/anthropics/claude-code/issues/95822), [#102265](https://github.com/anthropics/claude-code/issues/102265)). This undercuts CCSwitcher's delegated-refresh approach. A commenter on #95822 reports `claude -p /usage` as a safe trigger, because it waits for the refresh before fetching usage. That is a community claim, untested here.
3. **The usage endpoint is tightly rate limited per account.** After a 429 it can refuse for up to an hour ([ClaudeBar docs](https://github.com/tddworks/ClaudeBar/blob/main/docs/providers/claude/README.md)). The 429 is keyed on the account, not the client ([claude-swap#220](https://github.com/realiti4/claude-swap/issues/220)), and Anthropic's `/usage` shares the same budget ([Costs docs](https://code.claude.com/docs/en/costs)). Working cadences: ClaudeBar caches for 15 min; nerlichman polls every 3 min, backing off 1→5→10→15 min. The token endpoint's 429 escalates from 30 min to 24 h because "every attempt during a penalty window restarts it" ([nerlichman README](https://github.com/nerlichman/claudebar)).
4. **The Keychain item is one JSON blob shared with MCP logins.** It holds `claudeAiOauth` beside `mcpOAuth` and other keys, so a whole-item write signs the user out of MCP servers ([clauth `keychain.rs`](https://github.com/uwuclxdy/clauth/blob/mommy/src/keychain.rs), [claude-swap#450](https://github.com/realiti4/claude-swap/issues/450)). It can also hold only MCP state ([CodexBar#4731](https://github.com/steipete/CodexBar/issues/4731)), and it can outgrow `security -i`'s 4096-byte line buffer ([claude-swap `macos_keychain.py`](https://github.com/realiti4/claude-swap/blob/main/src/claude_swap/macos_keychain.py), [#104155](https://github.com/anthropics/claude-code/issues/104155)).
5. **Keychain grants are bound to the calling binary.** An "Always Allow" given to an ad-hoc-signed build dies at the next rebuild. clauth and ClaudeBar shell out to Apple's code-signed `/usr/bin/security` so the grant persists ([clauth `keychain.rs`](https://github.com/uwuclxdy/clauth/blob/mommy/src/keychain.rs), [ClaudeBar docs](https://github.com/tddworks/ClaudeBar/blob/main/docs/providers/claude/README.md)). Claude Code recreating its item also resets grants ([CodexBar docs](https://github.com/steipete/CodexBar/blob/main/docs/claude.md), [#3798](https://github.com/steipete/CodexBar/issues/3798)). This matters because code signing is out of scope for this app.
6. **The per-dir Keychain name is a hash of the exact path string.** The service is `Claude Code-credentials-<sha256(dir)[0:8]>` ([ClaudeBar design](https://github.com/tddworks/ClaudeBar/blob/main/docs/features/providers/multi-account/design.md), [clauth `keychain.rs`](https://github.com/uwuclxdy/clauth/blob/mommy/src/keychain.rs)). A symlinked or differently spelled path finds no login ([ClaudeBar in-use design](https://github.com/tddworks/ClaudeBar/blob/main/docs/features/in-use/design.md)); `$HOME/.claude` spelled out differs from unset ([#92252](https://github.com/anthropics/claude-code/issues/92252)); no tilde expansion or canonicalization ([#79223](https://github.com/anthropics/claude-code/issues/79223)).
7. **`CLAUDE_CONFIG_DIR` splits transcripts and plugin state.** Each dir has its own session history ([Authentication docs](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)), so tools must symlink `projects/` back (ccsw, caam) or accept split history (claude-swap without `--share-history`). Plugin index files store absolute, config-dir-rooted paths and must stay per profile ([ccsw README](https://github.com/jv-vogler/ccsw)). `.claude.json` is rewritten on every run and must stay a real file ([caam README](https://github.com/Dicklesworthstone/coding_agent_account_manager)).
8. **Logging out revokes.** "Do not run `/logout` first: current Claude Code may revoke the refresh token" ([claude-swap README](https://github.com/realiti4/claude-swap)). In the desktop app, Sign out "can end that sign-in on Anthropic's side" ([SnlperStripes README](https://github.com/SnlperStripes/claude-account-switcher)). Cleanup and undo flows must never call logout on a Profile the user wants to keep.
9. **Undocumented internals drift.** Claude Code's lock files changed in 2.1.218 ([claude-swap `claude_locks.py`](https://github.com/realiti4/claude-swap/blob/main/src/claude_swap/claude_locks.py)). Account email and organization moved off the `/usage` screen in CLI 2.1.79, so they now come from `~/.claude.json` ([ClaudeBar docs](https://github.com/tddworks/ClaudeBar/blob/main/docs/providers/claude/README.md)). New per-model windows appear only in `limits[]` ([#96716](https://github.com/anthropics/claude-code/issues/96716)). Desktop data paths changed on Windows ([SnlperStripes README](https://github.com/SnlperStripes/claude-account-switcher)).
10. **Spoofing and private client ids.** Some tools send Claude Code's or Safari's user agent ([Claude-Usage-Tracker source](https://github.com/hamed-elfayome/Claude-Usage-Tracker/blob/main/Claude%20Usage/Shared/Services/ClaudeAPIService.swift)), or reuse Claude Code's OAuth `client_id` to refresh or log in ([claude-swap `oauth.py`](https://github.com/realiti4/claude-swap/blob/main/src/claude_swap/oauth.py), [CCSwitcher README](https://github.com/XueshiQiao/CCSwitcher) on CodexBar). These break silently if Anthropic rotates the client id, and they sit uneasily with the [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance) rules.
11. **Disk and memory blow-ups from naive history or log scans.** Unbounded usage history ([Claude-Usage-Tracker#337](https://github.com/hamed-elfayome/Claude-Usage-Tracker/issues/337)), 106 GiB memory ([CodexBar#4512](https://github.com/steipete/CodexBar/issues/4512)), and re-parsing hundreds of MB of JSONL every 5 minutes ([CCSwitcher README](https://github.com/XueshiQiao/CCSwitcher)). Claude Code writes one JSONL line per content block, each repeating the usage object, and copies requests into several transcripts on rewind, so naive sums overcount ([ccusage adapter README](https://github.com/ccusage/ccusage/blob/main/rust/adapters/claude/src/README.md), [nerlichman README](https://github.com/nerlichman/claudebar)).
12. **Native notifications need provisioned signing.** nerlichman/claudebar reports that `UNUserNotificationCenter` banners need a Developer ID signature or embedded provisioning profile, so an unsigned build falls back to `osascript` banners ([README](https://github.com/nerlichman/claudebar)). That is the project's own empirical claim, unverified here. It affects threshold notifications if signing stays out of scope.
13. **Probe sessions pollute history.** Usage probes that run `claude` create sessions in `~/.claude/projects` and the `/resume` picker. CodexBar deletes its probe transcripts; ClaudeBar reuses one named session ([CodexBar docs](https://github.com/steipete/CodexBar/blob/main/docs/claude.md), [ClaudeBar docs](https://github.com/tddworks/ClaudeBar/blob/main/docs/providers/claude/README.md)).

## Worth reusing

Ideas:

- **Per-Profile config dirs owned by Claude Code**, created by running `claude auth login` with `CLAUDE_CONFIG_DIR` set, so the sign-in completes through Anthropic's own flow and Claude Code owns and refreshes the Keychain item ([ClaudeBar multi-account](https://github.com/tddworks/ClaudeBar/blob/main/docs/features/providers/multi-account/README.md)). Combine with **ccsw's symlink allowlist** to keep `projects/`, settings, skills and hooks shared and Profile state private, plus heal-on-launch and a read-only `doctor` ([ccsw](https://github.com/jv-vogler/ccsw)).
- **Switch new CLI runs by pointing a shell wrapper at a file holding the active Profile's folder** (never a key), installed into `~/.zshrc` only with consent and between marked lines so removal is clean ([ClaudeBar "In use"](https://github.com/tddworks/ClaudeBar/blob/main/docs/features/in-use/README.md)). Running sessions keep their Profile by construction, which matches the map's standing decision.
- **Identify Profiles by email plus organization UUID**, never display names or slot numbers ([CodexBar multi-account design](https://github.com/steipete/CodexBar/blob/main/docs/claude-multi-account-and-status-items.md), [claude-swap JSON in CodexBar docs](https://github.com/steipete/CodexBar/blob/main/docs/claude.md)). Refuse a folder whose login turns out to be a different person ([ClaudeBar multi-account](https://github.com/tddworks/ClaudeBar/blob/main/docs/features/providers/multi-account/README.md)).
- **Layer usage sources, freshest wins, and always label age**:
  - live A per Profile, at a conservative cadence with `Retry-After`-driven backoff and a separate token-endpoint penalty ramp ([nerlichman README](https://github.com/nerlichman/claudebar));
  - D from active CLI Sessions, credential-free;
  - E from the desktop app's `plan-usage-history.json`, credential-free, for desktop-used Organizations;
  - last-known values cached across relaunches with a capture-age marker. CodexBar never drives the menu bar icon from last-known data ([CodexBar docs](https://github.com/steipete/CodexBar/blob/main/docs/claude.md)).
- **Treat a rejected refresh as final** and show "Reconnect" rather than retry into a 429 ([nerlichman README](https://github.com/nerlichman/claudebar)). Hold Claude Code's own `proper-lockfile` locks around any credential write ([claude-swap `claude_locks.py`](https://github.com/realiti4/claude-swap/blob/main/src/claude_swap/claude_locks.py)).
- **Read-modify-write the Keychain blob, then read back and byte-compare** before believing a write ([clauth `keychain.rs`](https://github.com/uwuclxdy/clauth/blob/mommy/src/keychain.rs)). Pass secrets through `security -i` stdin, never argv, and watch the 4096-byte line limit ([claude-swap `macos_keychain.py`](https://github.com/realiti4/claude-swap/blob/main/src/claude_swap/macos_keychain.py)).
- **Unified session view inputs:**
  - `~/.claude/projects/**/*.jsonl` for history;
  - `~/.claude/sessions/{pid}.json` (per config dir; ccsw keeps `sessions/` per profile) with PID liveness for running Sessions;
  - desktop session titles;
  - open targets: `claude --resume <id>` in the session's `cwd`, a terminal tab by tty, or the desktop deep link `claude://claude.ai/claude-code-desktop/<id>` ([nerlichman README](https://github.com/nerlichman/claudebar), [ccrider README](https://github.com/neilberkman/ccrider), [search-sessions README](https://github.com/sinzin91/search-sessions)).
- **Sidebar sync prior art:** the SnlperStripes switcher copies `local_<id>.json` entries and `spaces.json` projects between `<account>/<org>` folders, never deletes, honours `deleted_<id>` tombstones, strips the other Organization's claude.ai project link, and keeps 10 backups ([README](https://github.com/SnlperStripes/claude-account-switcher)). Its token handling is outside our safety bar, but the sidebar rules are a tested starting point for the Sidebar sync ticket.
- **Desktop "switch" without touching secrets:** SnlperStripes shows that desktop switching means swapping encrypted token-cache entries in `config.json` plus the cookie file while the app is closed. That falls under safety-bar rule (2). Separate desktop instances with separate data dirs ([ckaridis/claude-multiple-accounts](https://github.com/ckaridis/claude-multiple-accounts)) are the only pattern seen that avoids copying secrets.

## Gaps this app would fill

- **A native Rust menu bar app for macOS.** Rust tools today are TUIs (clauth), Waybar widgets (ai-usagebar), Windows trays (CodeZeno, daybigo/ClaudeBar) or Tauri windows (claudometer, cc-switch).
- **Every Profile live at once with no token copies.** CodexBar delegates multi-account to `claude-swap`. Claude-Usage-Tracker refreshes only the active Profile ([#335](https://github.com/hamed-elfayome/Claude-Usage-Tracker/issues/335)). claude-swap and CCSwitcher keep second copies of credentials.
- **Profiles as Login + Organization.** Most tools key accounts by email; CodexBar and claude-swap only add the organization as a label when emails collide ([CodexBar docs](https://github.com/steipete/CodexBar/blob/main/docs/claude.md)).
- **Per-Profile config dirs that keep transcripts shared.** ClaudeBar's folders do not share `projects/`; ccsw shares them but has no usage view or menu bar.
- **A Unified session view across Profiles and clients.** Browsers read one `~/.claude/projects`; nerlichman/claudebar shows only running Sessions; nobody merges the desktop sidebar index with transcripts from every Profile's config dir.
- **Desktop switching inside the safety bar.** The only desktop switcher decrypts desktop secret storage; claude-swap's desktop request is open ([#14](https://github.com/realiti4/claude-swap/issues/14)).
- **Notifications plus "switch to the Profile with most headroom" without auto-switching.** Most switchers lead with auto-switch; ClaudeBar's nudge plus opt-in switch is the closest match.
- **Undo, uninstall and drift detection as first-class features.** Only SnlperStripes keeps rolling backups and claude-swap quarantines dead tokens; none documents a full restore of every touched file and Keychain item.

## Open questions for other tickets

- **Terms ticket:** does reading a Claude-Code-owned token from the Keychain to call `/api/oauth/usage` count as "intermediating" credentials ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance))? The answer decides between source A and a credential-free mix of sources C, D and E. It also bears on the standing decision "one credential per Profile; adding a Profile is one browser sign-in started from the tray": only `claude auth login` in a per-Profile dir keeps sign-in inside Anthropic's own flow.
- **Credential ticket:** whether to use the undocumented `CLAUDE_SECURESTORAGE_CONFIG_DIR` ([#79223](https://github.com/anthropics/claude-code/issues/79223)) to keep one shared config dir with per-Profile credential stores, instead of symlinks.
- **Refresh and staleness ticket:** whether to verify that `claude -p /usage` per Profile is safe (pitfall 2) and what it costs in rate-limit budget.
- **Notifications:** confirm pitfall 12 against Apple documentation before settling the notification design.
